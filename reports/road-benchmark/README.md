# Дорожное сравнение и статья

**[PDF](../dispatch-report.pdf)** · **[Typst](../dispatch-report.typ)** · **[45 результатов CSV](results.csv)**

Три исходных синтетических CSV: Восток (66 заявок), Юго-восток (83), Югоцентр (56).
По 15 запусков: Append, Insertion, fast (потолок 1 с), exact/GLS/CP-SAT (1/5/30/120 с).
Все запуски независимы и последовательны; каждый план перепроверен Rust-валидатором.

При 120 с, все заявки обслужены:

| Набор | Exact: штат / км | GLS: штат / км | Лексикографически лучше |
|---|---:|---:|---|
| Восток | 6* / 238,403 | 7 / 121,892 | Exact |
| Юго-восток | 8 / 888,377 | 9 / 521,603 | Exact |
| Югоцентр | 5 / 253,621 | 5 / 159,221 | GLS |

`*` — доказан минимум **штата**, не расстояния. На Востоке он достигнут уже при 5 с.
Полный лексикографический оптимум не доказан ни в одном из 45 запусков.
При равном покрытии меньший штат важнее любых километров.
Это по одному прогону конфигурации, не статистическое доказательство превосходства.

## Происхождение данных

- Реальные направленные дорожные таблицы OSRM/FOSSGIS, отдельные `routed-car`, `routed-bike`, `routed-foot`.
- Публичный Valhalla отклонил Юго-восток из-за ограничения 30 км; **все три** набора переведены на OSRM.
- Ни `fallback_speed`, ни расстояния по сфере не используются. Снимки содержат стоимости **без геометрии**.
- Координаты, общая база, навыки и смены 09:00–23:59 синтетические. Адреса не геокодированы/не подтверждены.
- E06/E12 (общественный транспорт) исключены явно; остаются 10 инженеров.
- Дорожные матрицы подготовлены вне времени оптимизации. Дополнительная проверка плана также вне таймера;
  внутренние проверки остаются внутри. `wall_ms` включает запуск процесса/импорт Python.
- OR-Tools 9.15.6755, Python 3.13.3, Apple M2 / 16 ГБ / macOS 27.0, один рабочий поток; CP-SAT seed 1.
- Данные © [OpenStreetMap contributors](https://www.openstreetmap.org/copyright), ODbL;
  [FOSSGIS](https://routing.openstreetmap.de/about.html), [исправить карту](https://www.openstreetmap.org/fixthemap).

## Артефакты

- `manifest.json`: CSV/сценарии/снимки/сырые ответы, URL, SHA-256 и время получения.
- `provider/`: 9 сырых HTTP-ответов, метаданные и нормализованные таблицы.
- `inputs/`: сценарии, `snapshots/`: отдельный кэш без геометрии — **не рабочий UI-кэш**.
- `runs/`: 45 итоговых JSON, 45 исходных ответов и stderr. Цель, таймеры, статусы, границы, порядок посещений.
- `environment.json`: фактически использованная среда и хэши кода/бинарника.
- `code/`: снимок использованных экспериментальных скриптов, Rust-ядра и Cargo; это архив для аудита,
  не отдельный самодостаточный проект (для сборки нужны также ресурсы основного проекта).
- `pilot/`: отдельные пробные запуски до фиксации runner; **не входят в 45 строк**.
- `results.csv`, `../article/results.json`: проверенная сводка для таблиц.

## Сборка статьи без нового эксперимента

Из корня проекта, без сети и без запуска решателей:

```sh
python3 scripts/summarize-road-benchmark.py
typst compile reports/dispatch-report.typ reports/dispatch-report.pdf
```

Аудит проверяет все хэши, каждую ячейку raw → normalized, комплектность 45 строк и
непротиворечивость доказанных глобальных префиксов относительно всех найденных планов.

## Новый эксперимент

**Сначала сохраните копию этого каталога и `reports/article/`: команды перезаписывают результаты.**

```sh
cargo build --release --locked
uv venv --python 3.13.3 .bench-venv
uv pip install --python .bench-venv/bin/python -r scripts/benchmark-requirements.txt
.bench-venv/bin/python scripts/test_bench_comparators.py
.bench-venv/bin/python scripts/test_road_benchmark.py
.bench-venv/bin/python scripts/road-benchmark.py
python3 scripts/summarize-road-benchmark.py
```

Текст выводов и статические числа статьи описывают исходный эксперимент: после новых
измерений их нужно сверить/обновить перед пересборкой PDF. Автоматически обновляются таблицы результатов.
Новый runner архивирует реально исполняемый код. `--resume` отклоняет расхождение хэшей кода
или записанных параметров среды **до перезаписи метаданных**. Хэш hostname не удостоверяет
физическую идентичность компьютера. Эта защита добавлена после исходных измерений;
архивный runner и его исторические хэши сохранены, алгоритмы/результаты не изменялись.

`python3 scripts/prepare-road-benchmark.py` нужен только для восстановления/создания входов.
С существующими raw-ответами сеть не используется; при их отсутствии будет девять публичных запросов
с интервалом ≥1,1 с. Для эксплуатационных объёмов нужен свой маршрутизатор, не публичный demo.

Для отдельного Rust-прогона обязательно указать benchmark-кэш:

```sh
DISPATCH_ROUTING_CACHE=reports/road-benchmark/snapshots \
  target/release/dispatch-sat solve reports/road-benchmark/inputs/east.json 30 exact
```

CLI `heuristic SCENARIO append|insertion` и `check-orders SCENARIO ORDERS` переиспользуют штатные
жадные процедуры и валидатор. `benchmark-matrix SCENARIO MATRIX` импортирует только таблицу
без геометрии и требует явного `DISPATCH_ROUTING_CACHE`; пользовательский HTTP API не расширялся.
